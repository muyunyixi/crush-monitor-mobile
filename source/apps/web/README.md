# Crush Monitor Mobile · 好感监控器移动版

面向手机浏览器的微信风格对话复盘工具。它可以导入聊天文本或截图，逐句整理对方的情绪与沟通意图、评价自己的回复，并生成适合保存和分享的长图。

[在线体验](https://muyunyixi.github.io/crush-monitor-mobile/) · [上游项目](https://github.com/FerryCorleone/crush-monitor) · [MIT License](LICENSE)

> 分析结果是 AI 根据有限文字作出的概率判断，不是读心、事实证明或关系结论。百分比表示模型在给定候选项中的倾向，不代表客观准确率；重要判断请结合完整上下文与当事人的直接表达。

## 功能概览

- 微信风格的移动端聊天界面，支持单条消息与整段记录导入。
- 对方消息展示情绪与沟通意图；我的消息展示回复质量评级。
- 提供心动指数、互动节奏、发言比例、关系阶段和下一步建议。
- 支持文本粘贴、剪贴板、TXT 文件和本地截图 OCR。
- 14 种本地对话彩蛋，不调用模型、不消耗分析额度。
- 可选择消息范围和内容模块，生成高清长截图。
- 无个人 Key 时，同一公网 IP 每个 UTC 自然日可免费发起 10 个分析批次；填写个人 TypeSafe API Key 后不受本站免费次数限制。

## 快速使用

1. 打开[在线页面](https://muyunyixi.github.io/crush-monitor-mobile/)。
2. 点击底部输入区域，选择当前关系并粘贴整段聊天；也可从“＋”中导入 TXT 或截图。
3. 检查识别的“我 / 对方”是否正确，必要时在文本框中调整。
4. 开始分析，逐句查看情绪、意图和回复评级。
5. 需要分享时，从“＋”中打开长截图功能，选择范围、模块和生成方案。

### Android 微信多选复制说明

微信在部分 Android 设备上会把多条消息写成多个剪贴板条目，而手机浏览器的原生长按“粘贴”通常只向网页提供第一个条目。此时网页收到数据前内容就已经被浏览器截断，JavaScript 无法还原后续条目；这不是聊天解析器主动删除内容。

可以使用以下任一方式完整导入：

1. 从输入法的“剪贴板”面板粘贴，而不是浏览器长按菜单。
2. 先在可完整接收的输入框中粘贴，再全选复制一次后导入网页。
3. 导入 UTF-8 TXT 文件。
4. 上传聊天截图并使用本地 OCR。

QQ 等应用通常把多条消息合并为一个剪贴板条目，因此一般不会触发这一限制。微信小程序使用的原生输入组件也可能完整接收多个条目，这与普通网页输入框的底层通道不同。

## 分析标签

### 情绪：12 种

| 类型 | 含义 |
| --- | --- |
| 开心 | 愉快、满足、开心或兴奋 |
| 疑惑 | 不理解、好奇、疑问或困惑 |
| 愤怒 | 真实生气、愤怒或强烈不满；排除亲密玩笑式骂人 |
| 难过 | 伤心、低落或悲伤 |
| 害羞 | 羞涩、难为情或暧昧时不好意思 |
| 关心 | 担心、关切或体贴对方 |
| 调侃 | 开玩笑、逗对方、玩梗或善意戏谑 |
| 平静 | 客观陈述或中性交流，没有明显情绪 |
| 不耐烦 | 厌烦、想结束话题或不愿重复解释 |
| 惊讶 | 意外、吃惊或超出预期 |
| 失落 | 期待落空、委屈或失望 |
| 难判断 | 文本不足、歧义较大或其他类别均不合适 |

### 沟通意图：35 种

意图描述一句话想完成什么，不等同于情绪，也不等同于隐藏心理。界面最多展示概率最高的 3 项。

| 分组 | 类型 |
| --- | --- |
| 信息交换 | 分享近况、回答问题、告知信息、询问信息、确认理解、解释说明 |
| 观点与承接 | 表达观点、表示认同、表达异议、回应收到、延续话题、转移话题 |
| 情绪沟通 | 玩笑逗趣、倾诉烦恼、寻求安慰、寻求认同、请求帮助、提供建议 |
| 支持与修复 | 表达关心、安慰支持、赞美欣赏、表达感谢、道歉修复、缓和气氛 |
| 关注与关系 | 寻求关注、试探好感、试探邀约、发出邀约、暧昧逗弄、表达在意 |
| 边界与收尾 | 婉拒提议、表达边界、结束聊天 |
| 兜底 | 其他意图、难以判断 |

### 如何理解百分比

- 百分比来自模型返回的候选概率，前端只做排序与四舍五入，不会重新归一化，也不会按关系状态人工加分。
- `开心 100%` 表示模型把该句的概率几乎全部分给“开心”，不表示情绪识别客观上百分之百正确。
- 当前关系会随对话一起提供给模型，帮助理解语气；它可能改变同一句话的上下文先验。但提示词明确规定：关系设置本身不是好感或情绪证据，普通玩笑不能仅因“恋爱中”就解释成暧昧。
- 短句、反话、表情包、不可见图片和上下文不足都容易造成过度自信或误判。意图通常比情绪更稳定，是因为“回答、提问、接话”等行为目的常有更直接的语言证据，而细微情绪更依赖语气和场景。

## 本地彩蛋：14 种

彩蛋只检查当前聊天文本、双方发言与时间戳，完全在浏览器本地运行。

| 彩蛋 | 触发方式 |
| --- | --- |
| 👑 御前频道 | 至少两条消息出现“朕 / 大皇帝 / 灵气复苏” |
| 🌙 月下信号 | 任一消息出现“月亮 / 月光 / 月色 / 星河 / 星星” |
| 😄 同频笑点 | 双方都出现连续“哈哈”或 `hh` 笑声标记 |
| 🏓 你来我往 | 至少 6 条消息，且相邻消息的发言人切换率不低于 80% |
| 🔁 默契回声 | 双方使用了相同的 2–4 字短语，并过滤常见无意义短语 |
| 🕯️ 夜航记录 | 时间戳落在 00:00–04:59 |
| 🍜 饭搭子频道 | 双方都提到吃饭、奶茶、火锅或面条等关键词 |
| 🎵 共享歌单 | 双方都提到歌曲、音乐、旋律或耳机 |
| 🐾 毛茸茸频道 | 双方都提到猫、狗、宠物或相关拟声词 |
| 🗓️ 未来便签 | 双方都提到下次、明天、周末或改天 |
| 🌿 善意回声 | 双方都表达谢谢、辛苦或感谢 |
| 📚 书页之间 | 双方都提到书、阅读、诗或小说 |
| 🎮 双人副本 | 双方都提到游戏、开黑、副本或组队 |
| ☁️ 同一片天气 | 双方都提到雨、晴、天气、风或雪 |

彩蛋是轻量规则匹配，不用于证明关系状态。例如“未来便签”只表示双方提过未来时间，不等于已经形成约定。

## 截图识字与长图导出

### 本地 OCR

- 使用 Tesseract.js、WebAssembly 和随站点发布的中英文模型在浏览器本地识别。
- 图片不会因 OCR 上传到项目服务器。
- 系统会尝试裁掉状态栏和输入区，并按照文字块的左右位置区分对方与自己。
- 背景复杂、表情包、装饰图标、超长气泡和低清截图仍可能误识别；导入前应检查文本。

### 长图方案

| 顺序 | 方案 | 适用情况 |
| --- | --- | --- |
| 1 | 标准原版 | 默认首选，保留页面原始排版 |
| 2 | Vivo 首选修复（桃子点这个） | 使用独立测量与 Canvas 绘制，绕开部分 Vivo 浏览器的字体基线偏移 |
| 3 | DOM 几何锁定 | 固定元素几何尺寸后再截图，适合布局漂移 |
| 4 | Canvas 全局 3px 校准 | 对 Canvas 文本基线作统一补偿 |
| 5 | 局部 2.5px 校准 | 仅修正气泡和标签等重点文字 |
| 6 | 局部 4px 强校准 | 偏移较明显时使用的加强版本 |

不同 Android 浏览器的字体度量、设备像素比和 Canvas 基线实现并不完全一致，因此项目保留多条独立生成路径，方便按设备选择。建议先用标准原版；只有生成图出现偏移时再切换修复方案。

## 免费额度与个人 Key

- 免费额度由 Cloudflare Durable Object 在后端记录，不依赖浏览器本地计数。
- 计数键为公网 IP 的 SHA-256 摘要与 UTC 日期；服务只用摘要定位额度桶。
- 同一次分析使用同一个批次 ID，拆分出的多个模型任务不会重复扣除免费次数。
- UTC 00:00 切换日期；中国标准时间对应每天 08:00。
- 页面进入或刷新时会请求 `/api/quota`，显示后端的实际剩余次数。
- 填写个人 TypeSafe API Key 后，Worker 使用该 Key 调用模型并跳过本站免费额度。
- 个人 Key 仅保存在当前页面内存，不写入 `localStorage`、`sessionStorage` 或仓库；刷新页面后需要重新填写。

## 隐私与安全

- 草稿消息保存在当前标签页的 `sessionStorage`，关闭标签页后由浏览器清理；也可在界面中主动清空。
- 本地 OCR 不上传原始截图。
- 进行 AI 分析时，所选聊天文字会经 Cloudflare Worker 发往 TypeSafe 模型服务，这是提供在线分析所必需的网络传输。
- Worker 不把聊天记录写入数据库；额度存储只保存日期和分析批次 ID。
- API Key、Cloudflare Token 等凭据不得写入源码、README、截图或公开 Issue。
